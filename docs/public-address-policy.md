# Public address policy

`gondolin.public-address/v1` is a conservative, pure Internet-unicast subset used by capability network rules with `internalRanges: "deny"`. It does not resolve names. The same predicate checks numeric-origin admission, resolution candidates and the actual Undici connection lookup callback. An allowed lookup candidate is not evidence of a completed socket or TLS handshake.

IPv4 requires Node's strict four-octet numeric grammar, without leading-zero, shortened, hexadecimal or integer spellings. IPv6 requires an unbracketed numeric address with no zone identifier. Hostnames, whitespace and malformed input deny. Canonical hostname parsing remains separate.

IPv4 excludes private, loopback, link-local, shared, documentation, benchmarking, protocol-assignment, multicast and reserved blocks, and all other special-purpose registry blocks, including their globally reachable exceptions. IPv6 supports only the RIR-allocated prefixes in the IANA global-unicast registry snapshot of October 10, 2025, with `2001:db8::/32` and `2620:4f:8000::/48` special-purpose exceptions excluded. The assignable `2000::/3` is not an allocation: all unlisted/reserved space, including returned `3ffe::/16` (6bone), denies. The exact allocation list is retained in `host/src/public-address.ts`; new allocations require an explicit reviewed update. Allocation indicates membership in this supported range profile, not actual routing or reachability. This deliberately excludes IPv4-mapped/compatible, NAT64, transition, site-local, link-local, ULA, multicast, discard-only and currently unallocated families. It is a supported subset, not a claim that every globally reachable special-purpose service is available.

IPv6 allocation membership derives from the [IANA global-unicast allocation table](https://www.iana.org/assignments/ipv6-unicast-address-assignments/); [RFC 3701](https://www.rfc-editor.org/rfc/rfc3701.txt) describes the 6bone phaseout and address return. The special-purpose exclusions derive from the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IANA IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry/), checked September 6, 2026; both report October 9, 2025 updates. [RFC 3879](https://www.rfc-editor.org/info/rfc3879/) deprecates IPv6 site-local addresses. Keep this versioned policy explicit when reviewing future registry assignments; unknown new protocols or alternative address representations do not gain authority by normalization.

Tests cover exclusion boundaries, malformed encodings, site-local and dummy-prefix regressions, and the production connection lookup guard calling the capability mediator with controlled DNS answers. These are host boundary regression tests; no real external socket/TLS observation or platform qualification is claimed. Production capabilities still require explicit destination, port, methods, resolution and redirect authority. `internalRanges: "allow"` remains a separate explicit wider grant; AdaptiveSandbox's public-only profile must never use it to make tests pass.
